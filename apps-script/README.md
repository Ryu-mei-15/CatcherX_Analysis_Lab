# CatcherX標準尺度・回答収集バックエンド

`evaluation.html`の参加者認証，回答保存，公開用集計をGoogle Apps Scriptと非公開Googleスプレッドシートで処理します．専用DBは不要です．

## 1．非公開スプレッドシートを作成する

回答保存用のGoogleスプレッドシートを新規作成します．このシートは一般公開せず，研究担当者だけに共有してください．

スプレッドシートの「拡張機能」→「Apps Script」を開き，このディレクトリの`Code.gs`をコピーします．マニフェストを表示する場合は`appsscript.json`も使用できます．

## 2．初期設定

Apps Scriptエディタから`setupCatcherXEvaluation`を1回実行し，必要な権限を許可します．次の3シートが作成されます．

- `Participants`：パスワードハッシュと利用条件
- `Responses`：認証済み回答
- `CredentialImport`：認証情報の一時取込

Apps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」で次を設定します．

| プロパティ | 設定値 |
|---|---|
| `ALLOWED_ORIGIN` | 公開サイトのオリジン（例：`https://example.github.io`） |

オリジンにはパスや末尾の`/`を含めません．`PASSWORD_PEPPER`，`SESSION_SECRET`，`SPREADSHEET_ID`は初期設定時に自動生成されます．これらを公開リポジトリへ記載しないでください．

## 3．参加者IDとパスワードを発行する

スプレッドシートを再読込すると「CatcherX」メニューが表示されます．

### 自動生成する場合

「CatcherX」→「認証情報を10件生成」を選択します．`CredentialImport`へ20文字のランダムパスワードが生成されます．参加者へ安全な方法で配布するために控えを取った後，「認証情報を取り込む」を実行します．取込後，平文パスワード欄は自動的に消去されます．

### CSVで指定する場合

非公開環境で次の列を持つCSVを作成し，`CredentialImport`シートへ貼り付けまたはインポートします．

```csv
participant_id,password,allowed_conditions,active,notes
P001,十分に長いランダム文字列,統合条件|捕球のみ|配球判断のみ,TRUE,
```

その後，「CatcherX」→「認証情報を取り込む」を実行します．CSVをこの公開リポジトリへ追加しないでください．

`allowed_conditions`には次のいずれかを`|`区切りで指定できます．空欄の場合は全条件を許可します．

- `統合条件`
- `捕球のみ`
- `配球判断のみ`
- `CatcherX全体`

既存IDを再度取り込むとパスワードと設定が更新されます．無効化する場合は`Participants`シートの`active`を`FALSE`にします．

## 4．ウェブアプリとしてデプロイする

Apps Scriptの「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選択します．

- 次のユーザとして実行：自分
- アクセスできるユーザ：全員

デプロイ後に表示される`/exec`で終わるURLを，ルートの`evaluation-config.js`へ設定します．

```js
window.CATCHERX_EVALUATION_CONFIG = Object.freeze({
    endpoint: 'https://script.google.com/macros/s/DEPLOYMENT_ID/exec'
});
```

コードを更新した場合は新しいバージョンとして再デプロイします．

## 5．保存・公開の動作

- IDとパスワードの一致時だけ30分間有効な署名付きトークンを発行します．
- パスワードはブラウザへ保存せず，認証要求後に入力欄から消去します．
- 実施日はブラウザの入力値を使わず，Apps Scriptが受信した日本時間の日付を記録します．
- 同じ参加者IDと実験条件の組合せは1回だけ登録できます．
- NASA-TLXとSUSはサーバ側でも値域を検証し，スコアを再計算します．
- `Responses`の`approved`が`TRUE`で，各条件3名以上集まった回答だけを，参加者IDを含まない集計値として公開します．公開から外す場合は`FALSE`へ変更します．
- 個別回答の確認とCSV出力は非公開スプレッドシート側で行います．

## 運用上の注意

- 認証情報のCSV，平文パスワード，スプレッドシートID，スクリプトプロパティを公開しないでください．
- 自動生成したランダムパスワードの利用を推奨します．
- 参加者への送付時はIDとパスワードを同一の公開資料へ掲載しないでください．
- 本実装は小規模な研究実験向けです．多数の同時接続や厳格なアカウント管理が必要になった場合は，認証基盤とDBを備えた構成へ移行してください．
